# SurvArena Benchmark Readiness Audit

**Researched:** 2026-09-01

**Scope:** Formal scientific benchmark, citable manuscript release, and future public/living benchmark

**Confidence:** HIGH for inspected code behavior; MEDIUM-HIGH for the synthesized maturity rubric

> **Verdict:** SurvArena is already a useful benchmark *framework* and a promising pre-release scientific kernel. It should not yet be presented as a citable, manuscript-grade, or “official” benchmark. Its current headline comparison layer can produce wrong win rates, wrong rank scales, and invalid fold-level inference; its data, HPO, prediction, provenance, and release contracts are not frozen strongly enough to make published scores durable. [VERIFIED: `survarena/evaluation/_ranking.py:10-123`; `survarena/evaluation/_significance.py:136-240`; `docs/test_status.md:38-44`; `docs/manuscript_publishability.md:5-24`]

## Summary

There is no single cross-domain certification that makes an ML benchmark “official”; this audit therefore uses an explicit three-tier maturity model. [ASSUMED] A **research-grade benchmark release** needs a frozen measurement contract, neutral task/method selection, leakage-safe paired evaluation, fair resource accounting, valid uncertainty, complete failure reporting, and reproducible artifacts. A **manuscript-grade release** additionally needs independently regenerated evidence, transparent reporting, limitations, and an archived release. A **public/living benchmark** additionally needs versioned submission rules, validation, review/audit, governance, and immutable leaderboard snapshots. These tiers synthesize the recurring requirements in neutral-comparison guidance, OpenML, TRIPOD+AI, FAIR/W3C provenance, and MLCommons. [CITED: https://pmc.ncbi.nlm.nih.gov/articles/PMC6584985/] [CITED: https://docs.openml.org/benchmark/] [CITED: https://www.bmj.com/content/385/bmj-2023-078378] [CITED: https://www.nature.com/articles/sdata201618] [CITED: https://mlcommons.org/benchmarks/]

|---|---|---|
| Benchmark toolkit/framework | **YES** | Config-driven runs, persisted outer splits, a broad Python adapter roster, censoring-aware metric implementations, manifests, retry/resume, and structured diagnostics exist. [VERIFIED: `configs/benchmark/manuscript_v1.yaml:1-119`; `survarena/data/splitters.py:224-388`; `survarena/logging/manifest.py:12-65`; `survarena/logging/export.py:366-508`] |

| Manuscript/citable release | **NO** | Retained matrices predate behavior-changing fixes, clinical HPO evidence is missing, the environment is not frozen, and final tables/figures have not been regenerated from a release artifact. [VERIFIED: `docs/manuscript_publishability.md:5-24`] |
| Public/living “official” benchmark | **DELIBERATELY DEFERRED** | The project explicitly defers a public leaderboard and governance platform until the scientific kernel is verified. This sequencing is correct. [VERIFIED: `.planning/PROJECT.md:45-51`] |

**Primary recommendation:** call the current product a **pre-release benchmark framework** or **benchmark kernel**. Reserve “citable benchmark release” for a frozen `survbench-1.0-rc1` that passes Gates A and B below; reserve “public/living benchmark” for Gate C.

These are the acceptance criteria against which the live repository was assessed; they are external criteria, not claims about current SurvArena behavior.

## Preliminary Live-Code Assessment

### P0 — scientific blockers

| Finding | Current evidence and failure | Required remediation / acceptance test |
|---|---|---|
| **Comparison kernel is mathematically wrong** | Dataset ranks pool all fold rows, pairwise wins compare the Cartesian product of method folds, and Wilcoxon treats matched fold/seed deltas as independent observations. A two-split executable counterexample where A beats B in both matched cells returns A win rate `0.75, n=4` rather than `1.0, n=2`, ranks A/B as `2/3` rather than `1/2`, and reports `n_pairs=4` for two datasets rather than inferential `n=2`. [VERIFIED: `survarena/evaluation/_ranking.py:10-123`; `survarena/evaluation/_significance.py:136-240`] | Match `protocol + arm + dataset + split + seed`; assert one row/method/cell; compute per-dataset effects; infer across datasets; enforce complete blocks; define the multiplicity family. Add adversarial multi-fold, mismatched-cell, incomplete-block, tie, missing, and reversal tests. |
| **Headline performance is conditional on success** | `eligible_frame()` drops failed, explicitly ineligible, and missing-metric rows; the leaderboard then aggregates the survivors. Complete common support is not a mandatory default, so a brittle method can be evaluated on an easier subset. [VERIFIED: `survarena/evaluation/_eligibility.py:24-43`; `survarena/logging/export.py:137-171`; `scripts/build_manuscript_elo.py:590-599`] | Make a predeclared complete common-support block mandatory for headline comparisons. Publish attempted/success/timeout/OOM/invalid/fallback coverage as a co-primary reliability view; never silently recode a fallback as success. |
| **Report identity can be rewritten or duplicated** | The manuscript script rewrites inputs to `benchmark_id=manuscript_v1` and `hpo_mode=no_hpo`, can load both compact and nested fold files without deduplication, and does not require strict coverage by default. [VERIFIED: `scripts/build_manuscript_elo.py:174-228`; `scripts/build_manuscript_elo.py:590-599`] | Generate reports only from a canonical collection query; reject mixed recipe/arm identities and duplicate run IDs; record collection digest, query/support policy, and report recipe in every output. |
| **Group safety is incomplete and can leak an identifier** | The outer splitter can be group-disjoint, but a declared `group_col` remains in `dataset.X`; it is read for splitting and also reaches preprocessing unless manually dropped. Inner HPO uses ordinary `StratifiedKFold`, and the final early-stop holdout uses row-level `train_test_split`. [VERIFIED: `survarena/data/loaders.py:83-99`; `survarena/benchmark/runner.py:257-321`; `survarena/benchmark/runner.py:1102-1120`; `survarena/benchmark/tuning.py:25-58`] | Store row ID and groups outside features by type, not convention. Make outer, inner, and early-stop partitions group-disjoint; fingerprint groups and row order; add deliberate leakage fixtures. |
| **Metric support and prediction validity are mutable/silent** | IPCW support is derived from maximum observed event time, requested horizons are clamped to fold-specific test support, and `25/50/75` horizons are training-fold event-time quantiles—so identically named columns can represent different absolute times. Non-finite risks are dropped; time grids are sorted/deduplicated rather than rejected; no central contract rejects bad shape, bounds, monotonicity, orientation, or unsupported prediction type. [VERIFIED: `survarena/evaluation/metrics.py:48-60`; `survarena/evaluation/metrics.py:86-129`; `survarena/evaluation/metrics.py:255-282`; `survarena/evaluation/metrics.py:512-524`; `survarena/benchmark/runner.py:372-394`] | Freeze per-dataset horizons/windows and exact IPCW estimator/support policy; store requested/used support and eligibility reason. Fail closed on invalid predictions. Differential-test C/IBS/AUC, independently validate calibration, and keep D-calibration as a diagnostic rather than a sole pass/fail test. [CITED: https://www.jmlr.org/papers/volume21/18-772/18-772.pdf] |
| **HPO labels and budgets are not truthful enough** | Optuna is not a declared dependency; when unavailable, HPO returns defaults with `optuna_missing`. All four foundation methods disable tuning in the HPO config while their rows retain the HPO arm label. Trial exceptions return infinities, timeout-truncated studies only warn, and an AutoGluon time-limit field is reused as every method's final-fit timeout. [VERIFIED: `pyproject.toml:13-64`; `survarena/benchmark/tuning.py:281-348`; `configs/benchmark/manuscript_hpo_v1.yaml:32-71`; `survarena/benchmark/runner.py:1161-1192`; `survarena/benchmark/runner.py:1272-1279`] | Fail the tuned arm closed when its tuner is unavailable or budget is truncated. Distinguish `tuned`, `default_only`, `unsupported`, and `truncated`. Separate execution, HPO, adapter-native, memory, worker, and thread budgets; record realized trials and full traces. |
| **A timeout does not stop the work** | Final fit runs in a thread; after timeout the code raises a failure row but explicitly cannot kill the runaway fit, so it can continue consuming resources and contaminate later timing/memory. [VERIFIED: `survarena/benchmark/runner.py:347-367`] | Run each fit in a disposable process/process tree; terminate on deadline plus grace period; measure per-unit peak RSS/CPU; test a deliberately hanging child process. |
| **Datasets are not release objects** | The seven clinical manuscript configs have `citation: null`; current dataset metadata has no first-class version, checksum, license, endpoint/follow-up definition, cohort relationship, or use restrictions. The loader silently replaces non-positive times with epsilon. [VERIFIED: `configs/benchmark/manuscript_v1.yaml:83-90`; current `configs/datasets/{support,metabric,nwtco,aids,gbsg2,flchain,whas500}.yaml`; `survarena/data/schema.py:62-77`; `survarena/data/loaders.py:140-170`] | Create immutable dataset cards/releases with hashes, citations/licenses, schema, time units/origin, event and censoring definitions, exclusions, transforms, groups, related cohorts, diagnostics, and fixed horizons. Make any target mutation explicit, versioned, counted, and tested. |
| **Canonical provenance is aspirational** | Live manifests record useful config/method/split hashes and selected package/environment data, but omit dataset release/hash, full dependency/model-weight identity, dirty-worktree state, container/recipe digest, and report query. The SQLite store is not the live runner source of truth and uses last-write-wins replacement for conflicting payloads. [VERIFIED: `survarena/logging/manifest.py:12-65`; `survarena/core/results/store.py:175-245`; `docs/test_status.md:41-43`] | Wire execution, resume/retry, merge, and reporting to one conflict-rejecting collection. Define run identity from protocol recipe, code, dataset, method/weights, split, arm, seed, environment, and hardware tier; make identical re-appends idempotent and divergent payloads fatal. |

## Where SurvArena Is Specifically Wrong Today

1. **“Pairwise” win rate is not paired:** it compares every A fold with every B fold. [VERIFIED: `survarena/evaluation/_ranking.py:54-123`]
2. **“Dataset ranks” are not on a method-within-dataset scale:** fold rows inflate the rank range. [VERIFIED: `survarena/evaluation/_ranking.py:10-51`]
3. **`n_pairs` is not the cross-dataset inferential sample size:** it counts correlated split/seed cells. [VERIFIED: `survarena/evaluation/_significance.py:151-225`]
4. **An `hpo` row may never have been tuned:** the tuner can be missing or deliberately disabled for that method. [VERIFIED: `survarena/benchmark/tuning.py:281-287`; `configs/benchmark/manuscript_hpo_v1.yaml:39-71`]
5. **A reported timeout is not execution containment:** the training thread may remain alive. [VERIFIED: `survarena/benchmark/runner.py:347-367`]
6. **`*_25`, `*_50`, and `*_75` are not fixed times:** they are per-training-fold quantiles and may be silently clamped. [VERIFIED: `survarena/evaluation/metrics.py:116-129`; `survarena/evaluation/metrics.py:512-524`]
7. **Group-aware outer CV does not make the pipeline group-safe:** the group can remain a predictor and inner/early-stop validation ignores it. [VERIFIED: `survarena/benchmark/runner.py:257-321`; `survarena/benchmark/runner.py:1102-1120`; `survarena/benchmark/tuning.py:25-58`]
8. **The current comprehensive artifact is not canonical:** live execution/reporting still relies on CSV-derived views, while the SQLite contract is not authoritative and silently overwrites conflicts. [VERIFIED: `survarena/logging/export.py:111-197`; `survarena/core/results/store.py:175-245`; `docs/test_status.md:42`]
9. **“Manuscript-grade” describes intent, not evidence:** the maintained publishability audit says the evidence bundle is not publication-ready. [VERIFIED: `docs/manuscript_publishability.md:5-24`]

## Security Domain

The current product is a local CLI/batch toolkit, so ASVS authentication, session, and web access-control categories are not presently applicable; input validation and supply-chain/artifact integrity are. [VERIFIED: `AGENTS.md:57-62`; `.planning/config.json:42-44`] YAML entry points use `safe_load`, which is a positive control. Predictor persistence uses `pickle.load`, and local dataset paths are joined to the repository root without an explicit confinement check; neither mechanism should ever accept an untrusted public submission. [VERIFIED: `survarena/config.py:18-23`; `survarena/data/loaders.py:71-82`; `survarena/api/_predictor_persistence.py:80-88`] A future public service needs sandboxed jobs, path confinement, artifact schema validation, authenticated release signatures/digests, secret isolation, dependency and model-weight provenance, upload limits, and a separate service threat model. [CITED: https://github.com/OWASP/ASVS]
